## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found 2026-09-24 during TASK-97's manual review of newly-labeled department_hint values: patterns.json's DEPT/other pattern lists include at least two unanchored substrings -- 'operations' (matches inside 'Kooperationspartner') and 'sucht' (matches inside 'gesucht') -- that produce false specialty labels. These were always present, but were low-impact while classification only scanned titles (short text, rarely contains these substrings by accident); TASK-97 widened classification to targeted body sections (Aufgaben/Profil), which are much longer and hit these collisions far more often -- measured 19/282 (6.7%) pure false positives in TASK-97's own newly-labeled sample, entirely attributable to this pre-existing regex-anchoring gap, not to TASK-97's section-boundary logic itself (which had 0 false positives on its own). TASK-107's later review of app/cv.py's skills fallback found the same class of collision independently (OP/Leitung matching inside Kooperation/Anleitung/Begleitung/contact-signature text). Likely other patterns in the same list share this gap; a full audit is warranted, not just these two.

FIX (AC#2) -- 5 targeted edits in pflege_jobs/patterns.json, each a narrow, live-evidence-driven anchor, NOT a blanket \b (which the task's own instructions warned would break German compound matching):
  department[OP].re:  operations -> \boperations              (left-anchor: blocks an unrelated prefix attaching before the pattern; every live legitimate form already starts the word)
  department[Psychiatrie].re: sucht -> (?<!ge)(?<!be)(?<!er)(?<!ver)(?<!unter)sucht   (negative lookbehind for the German verb-conjugation prefixes that produce a false hit: gesucht/besucht/ersucht/versucht/untersucht; every live legitimate Sucht-noun compound -- Suchterkrankungen, Suchtmedizin, Suchtpsychiatrie -- starts the word with no prefix, so these lookbehinds never fire on them)

  cv.skills[Psychiatrie].re and cv.skills[Chirurgie].re: same 2 exclusions ported for consistency (same bug, same file, same fix; zero risk since a lookaround exclusion can only remove a match, never add one)
