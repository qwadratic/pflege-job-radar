## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Обнаружено 2026-09-22 при попытке применить план TASK-86.

edge/pflege-ingest/index.ts делает upsert вида coalesce(nullif(excluded.col,''), stored) для колонок ats_type и careers_url. Это защита от частичного словаря, который занулил бы остальные поля, и для обычной записи она правильная. Но побочный эффект: ОЧИСТИТЬ любое из этих двух полей через edge-функцию нельзя в принципе -- пустая строка коалесцируется обратно в сохранённое значение.

Почему это важно на практике: ats_type определяет, каким раннером пойдёт борд. Бывает, что правильное действие -- именно снять метку, чтобы клиника ушла на общий wp_jobs-раннер вместо специализированного. Сейчас единственный способ это сделать -- прямой доступ к базе, который в рабочем окружении заблокирован.

Обходных путей не искать: записать явный способ очистки в саму edge-функцию.

Связано: TASK-86 (применение реестра), TASK-49 (там рекомендовалось очистить ats_type у клиник Allgaeu -- рекомендация оказалась неверной по другой причине, см. заметки TASK-86, но сам механизм очистки всё равно нужен).
